<span class="dropcap">I</span>n high school, our teacher taught us that an algorithm is a clear set of steps to solve any problem in a particular method through computer programming. At first, this went above and beyond my head, but I gradually learned that the algorithms that computers work on deal with numbers. We are grateful to Muhammad Alkhwarizmi, an early 9th century scientist, who first pioneered an algorithm. The word algorithm is derived from his last name, Alkhwarizmi.

## But what is an algorithm in programming exactly?

I would say that **an algorithm is a well crafted plan** that we carry out before implementing a solution through code to solve a problem. It's like if you want to go to travel by train, and you leave without booking a train ticket. This will either lead that you reach your destination late or not at all. Who knows how many train tickets are available when you go train station without prior booking? You will always need to plan first to solve a computational problem, and that planning is algorithm designing. This saves your code from becoming [spaghetti code](https://stackoverflow.com/questions/195520/what-is-spaghetti-code).

You do not need to design an algorithm every time you sit to code these days, because most of the algorithms are already available to use. Yet, one still needs to learn and plan the implementation.

## How does an algorithm look like?
Well, well, well! As said before, an algorithm is a plan. If you plan to do something, then you will have to take some steps. Defining your steps is actually writing an algorithm. Whenever I need to code, I first plan it using charts. We used to call them flowcharts. Many books have omitted the charts so, it has become difficult for self-educated developers to write quality code.

Here is how a flowchart looks like. See how it helps to execute each instruction and reach a final decision.

![A basic flowchart of an algorithm]({{site.url}}/images/basic-algorithm-flowchart.webp){:loading="lazy" width="300" height="400"}_A basic flowchart to repair or replace a bulb_

Let's see how we define each step in words.

```text
1. Our lamp is not working. We do not know what happened.
2. Let's check if the lamp is plugged.
3. If it is not plugged in, then please plug it. 🙂
4. It was plugged in; now what? See if the bulb is toasted. 🤔
5. If toasted, then replace the bulb.
6. But we found out that the bulb is fine. What to do now?
7. Let's repair the lamp so we could sit together and study.
```
In 7 perfect steps, we figured out that the fault was in our lamp. This could not be easier.

Now if we want to code the internet of things, we will take care of our lamps using the above algorithm.

## How to design an algorithm?
Designing an algorithm seems a little difficult, but it isn't that difficult. Professor Andrew Hilton, in his book *[All of Programming](https://aop.cs.cornell.edu/videos/index.html)*, shares some reasonable steps to designing an algorithm. I recommend the book if you are a STEM student.

I will share a generic strategy for designing an algorithm. Look at the lamp problem. What would be the first step if, in a sudden, you find out that the IoT lamp is not working at all? What would you do? Will you go to market and buy a new lamp? 

Probably, yes! 🤣

Even if you don't run to buy a new lamp, you might run to buy a new bulb. Quite possibly, isn't it?

How about if you check the plug first? Your cat might have loosened it. It's also possible that you might have received the "lamp down" notification on your phone already.

Now if you figured out that the lamp is plugged in, how about seeking more clues? For instance, if the bulb is okay. If it is not, we will buy a new one. If the bulb is not burned then perform a few more steps to see how the lamp could be turned on again.

## Conclusion
In programming, you will write down all your steps. After that you will begin coding to see you could solve the problem. There is no way to run from flowcharts. They are there to help you. It doesn't matter if you are a beginner or a seasonal developer. I have to give a thought, not just a thought, but a lot of time to design an algorithm for a problem.

It is better to invest time before implementing the code. It saves tons of hours. Your code won't become spaghetti. No one likes spaghetti code.

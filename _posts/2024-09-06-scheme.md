I am reading SICP book these days. The book uses scheme, a general purpose and
dynamically typed dialect of the LISP programming language. My main purpose to read this book is
to write beautiful programs, and scheme lang got a scheme to teach the beauty of
programming.

Well, I wanted to jot down the steps here about my installation process on
Fedora Linux for future needs. You may benefit.

MIT has upgraded scheme as Racket language, so I needed MIT/GNU-Scheme binaries
for Unix to install the compiler and REPL on Fedora. The installation procedure on [GNU webiste](https://www.gnu.org/software/mit-scheme/documentation/stable/mit-scheme-user/Unix-Installation.html) is fairly simple. I already had `make`, `m4`, and `ncurses-devel` packages installed. 

Although instructions on the above page were straight forward, I still got a
warning that make treated as an error. 

```
In file included from chacha12.c:49:
chacha.i:32:9: error: ‘_POSIX_C_SOURCE’ redefined [-Werror]
   32 | #define _POSIX_C_SOURCE 200809L
   |         ^~~~~~~~~~~~~~~
In file included from /usr/include/bits/libc-header-start.h:33,
                 from /usr/include/stdint.h:26,
                 from /usr/lib/gcc/x86_64-redhat-linux/16/include/stdint.h:11,
                 from chacha12.c:30:
/usr/include/features.h:319:10: note: this is the location of the previous
definition
  319 | # define _POSIX_C_SOURCE        202405L
      |          ^~~~~~~~~~~~~~~
cc1: all warnings being treated as errors
make[1]: *** [Makefile:182: chacha12.o] Error 1
make: *** [Makefile:753: microcode/scheme] Error 2
```

This is an easy to detect error. My system headers defined latest `_POSIX_C_SOURCE` as
`202405L`, and scheme source defines a redundant one. In my use case, I just
commented out the scheme's redundant definition `*/#define       _POSIX_C_SOURCE 200809L*/`, and ran `make install` again.

Voila, I got scheme running on Fedora Linux. C warnings are helpful, so keep
`-Werror` flag on all the time.

Post proelium, praemium.
